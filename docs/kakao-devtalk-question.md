로컬 API는 "지금 여기 남기기" 화면 한 곳에서만 씁니다. 사용자가 지금 있는 가게를 기록할 때 근처 음식점·카페 목록을 보여 주는 용도입니다. 아래 구조가 운영정책에 맞는지 확인 부탁드립니다.

**지금 바꾸려는 구조**

1. 사용자가 버튼을 누르면 서버(Cloudflare Worker)가 카테고리 검색(FD6, CE7, 반경 200~500m)을 실시간으로 불러 화면에 보여 줍니다. 서버는 응답을 캐시·로그·DB 어디에도 남기지 않습니다.
2. 사용자가 목록에서 한 곳을 고르면, 서버가 그 요청 안에서만 고른 장소의 장소명과 좌표를 써서 소상공인시장진흥공단 상가(상권)정보 API(반경 조회)에서 같은 가게를 찾습니다(이름 유사도와 거리 비교).
3. 찾으면 저장하는 것은 상가정보의 상호명·주소·좌표·상가업소번호와 카카오 장소 ID뿐입니다. 카카오 응답의 장소명·주소·좌표·전화·카테고리는 저장하지 않습니다.
4. 못 찾으면 카카오 장소 ID와 사용자 기기의 GPS 좌표(카카오 응답 좌표가 아님)만 저장하고, 가게 이름은 사용자가 빈칸에 직접 적게 합니다. 카카오 이름을 미리 채우지 않습니다.
5. 저장한 장소 ID는 "카카오맵에서 보기" 링크(https://place.map.kakao.com/{id})와, 같은 가게에 대한 사용자들의 짧은 평을 묶는 열쇠로 씁니다. 평의 본문은 사용자가 직접 쓴 글입니다.

**질문**

1. 위 2~4번처럼 카카오 결과를 요청 안에서 매칭에만 쓰고, 공공데이터 값과 카카오 장소 ID만 저장하는 구조가 허용되나요?
2. 5번처럼 장소 ID를 사용자 평을 묶는 열쇠로 쓰고, 그 평을 서비스 안의 다른 회원(초대받은 사람)에게 보여 주는 것은 괜찮을까요? 이때 화면에 보이는 가게 이름은 상가정보 상호명이나 사용자가 직접 쓴 이름입니다.
3. 예전 방식으로 이미 저장된 기록(사용자가 고른 한 곳의 카카오 장소명·주소·좌표)이 있습니다. 이를 같은 방법으로 상가정보와 한 번 매칭해 상가정보 값으로 바꾸고, 못 찾은 것은 장소 ID만 남기고 이름을 사용자에게 다시 받으려 합니다. 이 정리 방식에 문제가 없을까요?
4. 출처 표기는 목록 아래 "카카오맵 장소 정보"로 하고 있습니다. 더 지켜야 할 형식이 있으면 알려 주세요.

감사합니다.

## 답변 (2026-11-23) 요약과 반영

1. 카카오 응답의 장소명·좌표를 다른 API(상가정보) 조회 조건으로 쓰면 안 된다. 요청 중에만 쓰고 공공데이터 값만 저장해도 같다.
   → **반영**: 뒷단 `/match`(카카오 이름·좌표로 상가정보 찾기)를 없애고 `/stores?lat&lng`(내 폰 위치 둘레 150m)로 바꿈.
   지금 여기는 상가정보를 카카오 목록보다 먼저 받고, 고른 카카오 항목과는 폰 안에서 같은 곳인지 비교만 한다(`src/lib/storeMatch.ts`).
   공공데이터는 제공처 조건(공공데이터포털 이용허락)을 따른다.
2. 장소 ID를 우리 기록과 잇는 식별자로 쓰는 건 된다. 그걸 근거로 이름·주소·좌표까지 저장할 수는 없다.
3. 이미 저장한 카카오 응답을 다른 API 조회 조건으로 써서 대체 데이터를 얻는 것도 안 된다. 저장한 장소명·주소·좌표는 지우고,
   사용자에게 다시 받은 정보나 독립 자료로 정리. 카카오맵 연결용 장소 ID·URL은 둘 수 있다.
   → **할 일**: `scripts/kakao-audit.ts`로 먼저 세고(읽기만), 사용자 확인 뒤 정리. 11-23 고침 전 카카오 번호 기록은 공개할 때 이름을 다시 적게 함(`KAKAO_NAME_CUTOFF`).
4. 출처는 '카카오맵 오픈 API'로. → **반영**: 지금 여기 목록 아래와 출처 화면.
5. 카카오 API 기능은 무료로, 다른 자체 기능에 요금을 받는 건 된다. API 재판매나 카카오 API 기능 별도 과금은 안 된다.
   → 나중에 유료를 붙이면 '지금 여기 근처 목록'은 무료 쪽에 둔다.
