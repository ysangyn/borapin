# 보라핀 사진함 — 태그 없는 사진을 더 정확히 분류하는 알고리즘

작성 2026-11-07 · 상태: 설계(1단계 '알아내기'의 알맹이) · 기획안 v2(`PHOTO-DESK.md`) 4·5·6절을 **만들 수 있는 수준**으로 구체화한 것. 만들 때는 이 문서의 표와 숫자를 그대로 `desk/src/infer/`의 코드와 시험으로 옮긴다.

## 0. 한 장 요약

태그가 없는 사진은 **혼자 보면** 언제·어디를 알 수 없다. 그러나 **혼자인 사진은 거의 없다.** 같은 카메라의 앞뒤 번호, 같은 날 보라 폰이 찍은 사진, 카톡으로 받은 사진의 원본, 같은 폴더의 이웃, 사진 속 영수증 글자 — 이 가운데 하나만 있어도 자리와 시각이 번진다.

알고리즘은 다섯 마디다.

| 마디 | 하는 일 | 한 줄 |
|---|---|---|
| ① 증거 모으기 | 사진마다 '언제·어디·무엇'의 **증거 조각**을 다 꺼낸다 (EXIF·파일명·폴더·번호·글자·그림·받은 날…) | 버리지 않고 점수로 둔다 |
| ② 잇기 | 사진끼리 **이음**(순번·연사 / 쌍둥이 / 다른 폰 같은 순간 / 같은 폴더)을 만든다 | 번질 길을 놓는다 |
| ③ 번지기 | 확실한 사진의 언제·어디가 이음을 따라 번진다. 건너뛸수록 점수가 깎인다 | 기둥 보간이 여기 |
| ④ 묶기·맞추기 | 날 → 자리 묶음 → 나들이·여행 묶음으로 묶고, 묶음째 보라핀 여행과 맞춘다. 여행 아닌 사진(자료·일상·받은 사진)을 가른다 | 판단은 묶음 단위 |
| ⑤ 묻기 | 아직 모르는 묶음 가운데 **한 번 답하면 가장 많은 장이 풀리는** 것만 사람에게 묻고, 답을 다시 번지게 한다 | 한 번에 다섯 질문 |

정확도는 **'가리고 맞히기'**로 잰다: EXIF·GPS가 다 있는 우리 사진에서 일부러 가리고, 나머지 증거만으로 맞혀 보고 정답(가린 값)과 견준다. 사람이 표를 만들 필요가 없고, 매번 CI에서 돌릴 수 있다.

## 1. 문제 정의

### 1-1. 들어오는 것

| 입력 | 어디서 | 메모 |
|---|---|---|
| 사진·동영상 파일 | PC 폴더·외장·폰(USB/OneDrive 폴더)·폰에서 고른 파일 | 0단계 훑기(`desk/src/scan.ts`)가 읽는 것 그대로: 경로·크기·수정 시각·EXIF·GPS·카메라·해시 |
| 보라핀 기록 | 여행(날짜·지역), 가게·명소(좌표·이름·다녀온 날), 세계 도시·관광지 자료 | 앱 데이터 내보내기(`tripsExport`) + 번들 자료 |
| 같은 공간 사람의 사진 | 보라 폰의 목록(같은 형식) | 둘이 한 목록이라서 되는 기능 — 상대 사진이 내 사진의 기둥이 된다 |
| 집·회사 같은 '내 자리' | 설정(여러 곳) 또는 추정 뒤 확인 | 기기 밖으로 안 나감 |
| 보조 자료(선택) | 구글 타임라인 내보내기 JSON, Google Takeout의 JSON 사이드카(`photoTakenTime`·`geoData`), 폰 갤러리 태그 | 있으면 쓰고 없어도 된다 |
| 결제·교통 기록(선택) | 카드사 이용내역 엑셀, 승인 문자, 간편결제·교통카드·하이패스 내역 | 7-5. 기기 안에서만 읽음 |

### 1-2. 나오는 것 — 사진마다 넷, 근거와 함께

```ts
interface Belief<T> { value: T; score: number; conf: 'sure'|'guess'|'weak'; why: string[] }   // why: "DSC_0420(10:12 강릉)과 DSC_0422(10:40 강릉) 사이"
interface Inferred {
  when:  Belief<{ t0: number; t1: number; tz?: string }> | null;  // 구간. 점이면 t0===t1
  where: Belief<{ country?: string; region?: string; dong?: string; spot?: string }> | null;  // 층층이
  event: string;                                   // 자리 묶음 id
  trip:  Belief<string> | null;                    // 보라핀 여행 id
  kind:  Belief<'trip'|'outing'|'daily'|'stuff'|'received'>;  // 여행·나들이·일상·자료·받은 사진
  sub?:  'screenshot'|'document'|'receipt'|'menu'|'parking'|'delivery'|'food'|'scenery'|'people'|'selfie'|'pet';
}
```

- 값마다 **점수**(증거 합), **확신 셋**(확실·추정·약함), **근거 문장**이 붙는다. 화면에서 사진을 열면 근거 한 줄이 보이고, 틀리면 묶음째 고친다.
- 사진 파일은 안 건드린다. 결과는 목록(카탈로그)과 사이드카에만.

### 1-3. '태그 없는 사진'의 다섯 얼굴

| 얼굴 | 보통 어떤 상태 | 무엇으로 푸나 |
|---|---|---|
| A. 카톡·메신저로 **받은 사진** | EXIF 없음, 1280px 안팎, 파일명이 받은 시각 | 원본 쌍둥이(지각 해시) → 상대 폰의 같은 순간 → 받은 시각을 '상한'으로만 쓰고 여행 날짜와 맞춤 |
| B. **디카·미러리스** 사진 | 시각은 있으나 GPS 없음, 시계가 틀릴 수 있음 | 순번 이웃 → 두 폰의 GPS 기둥 보간 → 시계 보정 |
| C. **옛 사진·스캔** | 아무것도 없음, 폴더 이름만(`1999 신혼여행 제주`) | 폴더 이름 → 그림(계절·장면) → 확인함 |
| D. **스크린샷·문서·영수증** | 카메라 정보 없음, PNG/화면 크기 | 종류 가르기(자료) — 단 영수증·메뉴판은 글자가 자리의 단서 |
| E. **옮기다 벗겨진 사본** | 구글·에어드롭·Quick Share를 거치며 위치가 빠짐(삼성이 2026-04 Quick Share→AirDrop에서 위치 정보가 빠지는 문제를 인정) | 쌍둥이(같은 파일 해시 또는 지각 해시) → 원본에서 이어받음 |

## 2. 원칙 다섯

1. **혼자 판단하지 않는다.** 사진 한 장의 답은 이웃·쌍둥이·다른 폰·묶음에서 온다. 혼자인 사진만 '모름'이다.
2. **근거를 남긴다.** 모든 값에 "어디서 왔는지"가 붙는다. 근거 없는 값은 쓰지 않는다.
3. **틀려도 안전하다.** 원본 불변, 결과는 목록·사이드카, 되돌리기 가능. '추정'은 공개 지도·스토리 카드에 쓰지 않는다.
4. **확신은 셋뿐이다.** 확실·추정·약함. 확률을 보여 주지 않고, 셋의 뜻이 실제 정확도와 맞게 보정한다(9절).
5. **사람은 묶음에 한 번.** 한 장씩 묻지 않는다. 한 번 답하면 수백 장이 따라온다.

## 3. 증거 조각과 점수표

점수는 "이 증거가 맞을 확률"을 대충 로그 승산으로 바꾼 것(5 = 거의 확실, 1 = 참고). 처음 값은 아래이고, **가리고 맞히기(9절)로 다시 맞춘다.** 표는 코드에서 `WEIGHTS` 한 곳에만 둔다.

### 3-1. 언제 (시각)

| 증거 | 주는 것 | 점수 | 메모 |
|---|---|---|---|
| EXIF 촬영 시각 + 시간대(`OffsetTimeOriginal`) | 분 | 5.0 | 폰은 거의 다 있음 |
| EXIF 촬영 시각(시간대 없음) | 분 | 4.5 | 시간대는 자리에서(5-3) |
| 동영상 `creation_time`(UTC)·`com.apple.quicktime.creationdate` | 분 | 4.5 | 안드로이드 mp4는 UTC라 시간대가 꼭 필요 |
| Takeout JSON `photoTakenTime` · XMP 사이드카 | 분 | 4.5 | 구글에서 내려받은 사진의 벗겨진 시각 복구 |
| 쌍둥이(같은 해시)의 시각 | 분 | 4.8 | 완전히 같은 파일 |
| 쌍둥이(지각 해시 ≤ 6비트)의 시각 | 분 | 4.0 | 메신저 재압축 사본 |
| 카메라 앱 파일명(`20190812_183000`, `IMG_20240503_101533`, `PXL_…`, `Screenshot_2024-05-03-10-15-22`) | 초 | 4.0 | 카메라 앱이 붙인 이름은 촬영 시각 |
| 순번 이웃(`DSC_0421`이 `0420`(10:12)과 `0422`(10:40) 사이) | 구간 | 3.5 | 같은 카메라 몸체, 같은 날일 때. 9999 넘김 처리 |
| 사진 속 글자의 날짜(영수증·티켓·탑승권 `2019.08.12`) | 날 | 3.0 | 영수증 날짜 = 그날 |
| 폴더 이름의 날(`2024-05-03 제주`) | 날 | 2.5 | 사람이 만든 폴더 |
| 폴더 이름의 달·해(`2024-05`, `2019년 강릉`) | 달·해 | 2.0 / 1.5 | |
| 받은 사진의 파일명(`KakaoTalk_20190813_221005`) | **상한** | 1.0 | 찍은 때는 이보다 앞. 값이 아니라 '≤' 제약으로만 |
| 수정 시각(mtime)이 이웃·폴더 구간 안 | 날 | 1.5 | 카메라에서 복사한 파일은 mtime이 촬영 시각인 경우가 많음 — 이웃과 맞을 때만 |
| 수정 시각(mtime) 혼자 | 날 | 0.5 | 마지막 수단 |
| 그림의 계절(눈·벚꽃·단풍·반팔) | 달 범위 | 0.8 | 제로샷 라벨. 보조 |
| 그림의 낮·밤 | 시간 범위 | 0.5 | 시계·시간대 틀림 잡는 데 더 쓸모(5-3) |

### 3-2. 어디 (자리)

| 증거 | 주는 것 | 점수 | 메모 |
|---|---|---|---|
| EXIF GPS | 좌표 | 5.0 | 단 **묵은 좌표** 검사(5-6): 비행기 내린 직후 첫 사진이 출발지 좌표인 경우 |
| 동영상 위치(`©xyz`, ISO 6709) | 좌표 | 4.8 | |
| 쌍둥이의 좌표 | 좌표 | 4.8 / 4.0 | 같은 해시 / 지각 해시 |
| 다른 폰 같은 순간(±2분, 같은 공간 사람) GPS | 좌표 | 4.5 | ±10분이면 4.0, ±1시간이면 3.0 — 거리는 이동 속도로 검산 |
| 구글 타임라인(그 시각의 점·방문) | 좌표·장소 | 4.0 | 있을 때만 |
| GPS 기둥 보간(앞뒤 기둥 같은 지역, 6시간 안) | 지역(+동네) | 4.0 | 4-4 규칙. 같은 동네면 동네까지 |
| GPS 기둥 보간(하룻밤 넘김 / 다른 지역 사이) | 지역 | 2.5 | '이동 중' 구간 |
| 사진 속 글자: **전화 지역번호**(033→강원, 064→제주…) · 주소 토큰(`강릉시 주문진읍`) · 가게 이름(보라핀 기록·관광지 자료와 일치) · 역·정류장 이름 | 지역~가게 | 3.5 (고유 일치) / 2.0 (후보 여럿) | 영수증 한 장이 그날 전체의 기둥이 된다 |
| 사진 속 글자: 통화·문자(¥·€·฿·가나·태국 글자) | 나라 | 2.0 | 해외 여행 구분 |
| 보라핀 여행 기록(그 날짜의 여행 지역) | 지역 | 2.5 (지역 하나) / 1.5 (여러 지역) | 날짜가 확실할 때만 |
| 보라핀 가게 기록(같은 날 다녀온 가게 좌표) | 가게 | 3.0 (±30분) / 2.0 (같은 날) | |
| **카드·간편결제 승인**(가맹점 자리를 알 때, 사진 앞 2시간~뒤 15분) · 교통카드·하이패스(승하차·IC와 시각) | 지점 / 이동 중 | 4.0 / 3.0 | 7-5. 숙박 결제는 그날 밤 지역 3.5 |
| 그림 ↔ 우리가 간 곳 프로토타입(이미 확실한 사진들의 임베딩 kNN, 코사인 ≥ 0.90) | 지점 | 2.5 | 같은 절·같은 카페를 다시 찍은 사진. 쓸수록 늘어나는 기억 |
| 그림 ↔ 지역 꼬리표(바다·산·절·시장 ↔ 세계 도시·관광지 자료의 꼬리표) | 지역 후보 | 1.0 | 약한 보조. 후보를 줄이는 데만 |
| 집 반경 안(설정한 내 자리) | '일상' 쪽 | — | 자리값이 아니라 종류(5-9)에 쓴다 |

## 4. 이음 네 가지 — 번질 길

| 이음 | 조건 | 번지는 것 | 깎임 |
|---|---|---|---|
| **순번·연사** | 같은 카메라(모델+일련번호 또는 같은 접두 `DSC_`) · 번호 차 ≤ 50 · 시각이 있는 쪽끼리 같은 날 | 시각 구간, 자리 | 번호 차 1당 −0.05, 날 넘으면 끊음 |
| **쌍둥이** | ① 같은 SHA-256 → 같은 사진 ② dHash/pHash 차 ≤ 6비트 → 재압축 사본 ③ 임베딩 코사인 ≥ 0.95 → 자른·보정한 사본 | 시각·자리·여행·종류 전부 | ①0 ②−0.8 ③−1.5 |
| **다른 폰 같은 순간** | 같은 공간 사람의 사진과 시각 차 ≤ 2분(시간대 맞춘 뒤) · 둘 다 GPS 있으면 거리 ≤ 500m여야 함(아니면 한쪽이 묵은 좌표) | 자리 | 시각 차 1분당 −0.1, 10분 넘으면 3.0까지, 1시간 넘으면 끊음 |
| **같은 폴더·같은 묶음** | 사람이 만든 폴더(날짜·지명이 든 이름) 또는 5-7의 자리 묶음 | 자리·여행·종류 | 폴더 −1.0, 묶음 −0.5 |

이음은 **그래프**다. 번지기는 그래프 위에서 "확실한 사진 → 이음 → 이웃"으로 점수를 전하되 깎인 점수가 1.0 아래면 전하지 않는다. 최대 세 바퀴(3바퀴면 거의 다 멈춘다).

## 5. 알고리즘 — 단계

```
입력: items(파일), trips, places, homes, others(상대 목록), aux(타임라인·Takeout)
 1. normalize   파일 → 고유 사진(중복 합침) · 증거 조각 꺼내기 (3절)
 2. facts       점수 ≥ 4.5 증거는 '사실'로 고정
 3. clocks      카메라 시계 어긋남·시간대 추정 → 시각 보정(제안·근거 남김)
 4. links       이음 그래프 (4절)
 5. spreadWhen  시각 번지기 (구간 교집합 + 점수 합)
 6. spreadWhere 자리 번지기 (기둥 보간 + 속도 검산 + 글자 기둥)
 7. cluster     날 → 자리 묶음 → 나들이·여행 묶음
 8. matchTrips  묶음 ↔ 보라핀 여행, 기록 없는 여행 발견
 9. kinds       자료·받은 사진·일상·나들이·여행
10. ask         질문 고르기 → 답 → 2로 돌아가 다시(최대 3바퀴)
출력: Inferred[] + 질문 목록 + 평가표
```

### 5-1. 정규화

- 같은 SHA-256은 한 사진(`uniquePhotos`). 사본들의 증거는 **합친다**(사본 하나에 EXIF가 남아 있으면 그것이 모두의 것).
- 모든 시각은 "ms(UTC) + 시간대"로. 시간대를 모르면 비워 두고 5-3에서 채운다.
- 파일명·폴더명 규칙은 `desk/src/names.ts`(이미 있음)에 보탠다: 카톡은 **받은 시각**, `Screenshot_`은 스크린샷, `PXL_`은 UTC 기준 이름 등 규칙마다 '무엇을 뜻하는지'를 표로 둔다.

### 5-2. 사실 고정

점수 4.5 이상인 증거(EXIF 시각·GPS·같은 해시 쌍둥이·카메라 앱 파일명)는 사실로 고정하고, 번지기는 사실을 바꾸지 않는다. 단 5-3·5-6의 **검산에 걸린 사실**은 '의심'으로 낮춘다(4.5 → 2.0, 근거에 이유).

### 5-3. 시계·시간대 검사 (디카·해외 여행의 핵심)

| 검사 | 방법 | 결과 |
|---|---|---|
| GPS 시각 vs 촬영 시각 | EXIF 안의 `GPSDateStamp`+`GPSTimeStamp`(UTC)와 촬영 시각 차 → 시간대 = 차이(정수 시간에 가까우면). 분 단위 어긋남 → 시계 오차 | 시간대·오차 추정 |
| 두 기기 같은 장면 | 디카 사진과 폰 사진의 지각 해시·임베딩이 같은 장면(≥ 0.92)인 쌍을 모아 시각 차의 **중앙값** → 디카 시계 오차 | "이 카메라는 7시간 2분 빠름" 제안 |
| 낮·밤 검산 | 자리를 아는 사진의 (위도·경도·시각)으로 해 높이를 계산(SunCalc). 밝은 야외 사진인데 해가 −12° 아래(한밤) → 시간대나 시계가 틀림 | 의심 표시, 후보 시간대 제시 |
| 속도 검산 | 이웃 GPS 사진 사이 거리/시간 > 1,000km/h → 한쪽 시각·자리가 틀림. 이웃이 더 많은 쪽을 믿는다 | 의심 표시 |
| 여행 나라 | 날짜가 보라핀 해외 여행 안이고 카메라에 시간대가 없으면, 여행 도시의 시차(`world.json`)를 시간대로 | 시간대 채움 |

시계 보정은 **제안만**(기획안 10절 기본값). 사람이 "맞아요"를 누르면 그 카메라·그 기간의 모든 사진에 번진다. 보정 전 값도 근거에 남긴다.

### 5-4. 이음 만들기

4절 그대로. 쌍둥이 찾기는 ① 해시 표 → ② dHash 64비트를 BK-트리 또는 다중 인덱스(16비트 조각 4개)로 ≤ 6비트 이웃 찾기 → ③ 임베딩은 있을 때만. 10만 장에서도 ②는 수 초.

### 5-5. 시각 번지기

- 사진의 시각 후보는 **구간**이다. 증거마다 구간(점·날·달·해·'≤ 받은 시각')과 점수가 있다.
- 합치기: 서로 겹치는 구간들의 점수를 더해 가장 점수 높은 **겹침 구간**을 고른다. 같은 덩어리 안에서는 **교집합**을 값으로(폴더 '2024-05' ∩ 순번 이웃 '5월 3일 10:12~10:40' = 10:12~10:40).
- 충돌(EXIF 2019-08-12 vs 폴더 2024-05): 높은 점수가 이기되, 진 쪽 점수가 2.0 이상이면 '충돌' 꼬리표를 달아 확인함 후보로(파일이 엉뚱한 폴더에 들어간 경우가 보통이라 EXIF가 맞다).
- 순번 이웃 구간은 **번호 비례**로 좁힌다: `0420`=10:12, `0423`=10:40이면 `0421`≈10:21±5분(약함이 아니라 추정).

### 5-6. 자리 번지기 — 기둥 보간

기둥 = 자리 점수 ≥ 4.0인 사진(GPS·쌍둥이·다른 폰·글자 고유 일치). 시각이 있는 사진을 시각 순으로 늘어놓고, 각 사진의 앞 기둥 P와 뒤 기둥 N을 본다.

| 경우 | 값 | 점수 |
|---|---|---|
| P·N 같은 지역, 사이 ≤ 6시간 | 지역 = P. 같은 동네면 동네까지. 두 기둥 거리 ≤ 1km이고 사이 ≤ 1시간이면 **지점**(P 좌표) | 4.0 (지점 3.5) |
| P·N 같은 지역, 6시간 ~ 하룻밤 | 지역만 | 3.0 |
| P·N 다른 지역(강릉→속초) | P에서 1시간 안 = 강릉, N에서 1시간 안 = 속초, 가운데 = '강릉→속초 길' | 2.5 |
| P·N 사이에 못 갈 거리(30분에 200km) | 보간 안 함 → 5-3으로 | — |
| 한쪽 기둥만 | 3시간 안이면 같은 지역, 더 멀면 비움. 여행 날짜 안이면 여행 지역(2.5) | 3.0 / 2.5 |
| 기둥이 하나도 없는 날 | 글자·여행 기록·그림 후보로(3-2 아래쪽) | 각 점수 |

**묵은 좌표**: 앞 사진과 좌표가 같은데(≤ 50m) 그 사이 시간에 비해 뒤 사진들이 멀리 있으면(예: 3시간 뒤 사진들이 300km 밖) 그 좌표는 폰이 기억한 옛 위치 → 점수 5.0 → 1.0으로 낮추고 근거에 적는다.

**글자 기둥**: 영수증·간판에서 고유하게 맞은 가게(보라핀 기록·관광지 자료)는 좌표가 있으니 기둥이 된다. 지역번호·주소 토큰은 지역 기둥(지역만 번진다).

### 5-7. 묶기

| 층 | 자르는 규칙 | 쓰임 |
|---|---|---|
| **날** | 현지 시각 기준, 하루의 시작은 **04:00**(새벽 1시 사진은 전날 밤) | 서랍의 '5월 3일' |
| **자리 묶음** | 날 안에서 ① 시간 간격이 이웃 간격의 기하평균 × K(K=12, 창 ±10장, 바닥 20분·천장 3시간)를 넘거나 ② 거리 > 2km(자리 아는 사진끼리)면 자른다. PhotoTOC(Platt 2003)의 적응 간격 규칙을 바닥·천장과 함께 | 한 가게·한 명소 = 한 묶음. 이름 붙이기 단위 |
| **나들이·여행 묶음** | 날들을 잇는다: 그날 자리 아는 사진의 절반 이상이 집 반경(기본 3km, 여러 곳) 밖이고, 앞날과 36시간 안이면 같은 묶음. 하룻밤 이상 = 여행 후보, 당일 = 나들이 | 보라핀 여행과 맞추는 단위 |

- 시각이 '약함'(mtime 혼자)인 사진은 묶음의 **기준이 되지 않는다.** 묶음이 만들어진 뒤 폴더·쌍둥이·그림 닮음으로 붙는다.
- 묶음에 든 사진 가운데 자리를 아는 것이 하나라도 있으면 묶음의 자리가 되고, 자리 모르는 구성원에게 번진다(점수 −0.5).

### 5-8. 여행 맞추기와 발견

나들이·여행 묶음 E와 보라핀 여행 T마다:

```
score(E,T) = 3.0 × 날짜겹침(E가 T 날짜 안에 든 비율, 앞뒤 하루 여유)
           + 2.0 × 자리맞음(E의 지역 ∈ T.places → 1, 같은 도, 인접 → 0.6, 모름 → 0.5, 다른 지역 → 0)
           + 1.0 × 이미 이어진 사진 비율(E 안에 T로 확실한 사진이 있으면)
```

- 가장 높은 T를 고르고, 2등과 차이가 1.5 이상이고 점수 ≥ 4.0 → 확실, 점수 ≥ 2.5 → 추정, 그 아래 → 약함.
- 같은 날 여행이 둘(당일 두 지역)이면 자리맞음이 가른다. 자리도 모르면 '추정'으로 두고 확인함.
- **기록 없는 여행**: 집 밖 하룻밤 이상인 묶음이 어느 여행과도 2.5를 못 넘기면 "여행으로 만들까요? 2019-08-12~14 · 강릉(GPS 31장·영수증 2장)" 후보를 낸다. 날짜·지역·사진 수를 채워 주고, 만들면 즉시 이어진다.

### 5-9. 종류 가르기

순서대로 처음 맞는 것:

1. 스크린샷·문서·영수증·메뉴판·주차·택배 증거 ≥ 4.0 → **자료**. 여행 묶음 안에 있어도 자료(책·올리기에서 빠짐, 전체 보기에선 보임). 영수증·메뉴판은 글자를 5-6·가게 후보로 쓴다.
2. 받은 사진 증거 ≥ 4.0이고 쌍둥이 원본이 없음 → **받은 사진**. 여행 묶음과 이어지면 "함께 간 사람이 보내 준 사진"으로 그 묶음에 끼움(받은 날이 여행 끝 +3일 안이고, 그림이 묶음의 사진과 닮음 ≥ 0.85일 때).
3. 묶음이 여행과 이어짐 → **여행**.
4. 묶음이 집 밖 당일 → **나들이**(맛집·명소 '다녀왔어요' 후보).
5. 나머지 → **일상**(집 반경 안·회사 근처·자리 모름).

틀린 판단을 고치면 **같은 조건에 번진다**: "회사 근처 점심은 일상" → 그 자리 반경 500m·평일 12~13시 묶음 전부. 규칙은 사람이 고친 것만 쌓이고, 화면에서 보인다·지울 수 있다.

### 5-10. 묻기 — 질문 고르기

- 후보: 확신이 '추정'·'약함'이거나 '충돌'인 **묶음**(사진 아님).
- 고르는 값 = **한 답으로 풀리는 사진 수 × (1 − 지금 점수/5)**. 큰 것부터 다섯 개.
- 질문은 늘 **가장 그럴듯한 답을 채워서**: "이 37장, 2019년 8월 강릉 여행 맞아요?" → [맞아요] [다른 여행…] [여행 아님] [나중에]. 근거 한 줄과 대표 사진 6장을 같이 보인다.
- 답은 사실(5.0)로 고정하고 2단계부터 다시 돈다. 답 하나로 같은 카메라·같은 날·같은 폴더까지 번진다.
- 묻지 않는 것: 자료로 가른 사진(틀려도 숨김일 뿐), 쌍둥이가 있는 사진, 한 장짜리 묶음(나중에 '모르는 사진' 서랍에서 끌어다 놓기).

### 5-11. 되풀이와 멈춤

2→10을 **최대 세 바퀴**. 바퀴마다 '모르는 사진' 수를 기록한다. 한 바퀴에 줄어든 수가 1% 미만이면 멈춘다. 10만 장 기준 목표: 메타만으로 한 바퀴 30초 안(순수 TS), 글자·그림 층은 미리 계산해 목록에 넣어 두므로 바퀴 시간에 들어가지 않는다.

## 6. 점수 → 확신

| 확신 | 조건 | 뜻(사람에게) | 보정 목표(9절) |
|---|---|---|---|
| 확실 | 최고 점수 ≥ 4.0 이고 2등과 차 ≥ 2.0 | "맞다고 보면 된다" | 실제 정확도 ≥ 97% |
| 추정 | 최고 점수 ≥ 2.0 | "아마 그렇다 — 틀리면 알려 달라" | ≥ 80% |
| 약함 | 그 아래, 0 초과 | "짐작일 뿐" — 서랍에서 `?` 표시 | 기록만 |
| 모름 | 증거 없음 | '모르는 사진' 서랍 | — |

확신의 뜻이 실제와 어긋나면(확실인데 90%) 점수 문턱이나 가중치를 고친다. 문턱·가중치는 코드의 한 표, 바꿀 때마다 9절 채점이 CI에서 돈다.

## 7. 내용 층 — 글자·그림·사람·품질

메타만으로 못 푸는 사진(A·C·E 얼굴)을 위해 **기기 안에서** 돌리는 네 층. 결과는 목록에 저장하고 번지기는 저장된 결과만 읽는다(무거운 계산과 판단을 떼어 놓는다).

### 7-1. 글자(OCR) — 자리의 가장 센 단서

| 뽑는 것 | 규칙 | 쓰임 |
|---|---|---|
| 전화 지역번호 | `0△-△△△(△)-△△△△` 꼴에서 앞 번호가 02 서울·031 경기·032 인천·033 강원·041 충남·042 대전·043 충북·044 세종·051 부산·052 울산·053 대구·054 경북·055 경남·061 전남·062 광주·063 전북·064 제주 (휴대폰 010은 제외) | 지역 기둥(3.5) |
| 주소 토큰 | `○○시/○○군 + ○○구/읍/면/동` 꼴 → 행정동 자료와 맞춤 | 지역·동네 기둥 |
| 가게 이름 | 글자 줄 ↔ 보라핀 가게·관광지 자료 이름(편집 거리 ≤ 1, 2글자 이상) | 지점 기둥·'다녀왔어요' 후보 |
| 날짜 | `20\d\d[.\-/년 ]\s?\d{1,2}[.\-/월 ]\s?\d{1,2}` · 영수증의 승인 시각 | 시각(3.0) |
| 역·정류장·도로 표지 | `○○역·○○터미널·○○IC·○○휴게소` 꼴 ↔ 자료 | 지역·이동 중 |
| 통화·문자 | `¥ € $ ฿ ₫` · 가나·태국·베트남 글자 비율 | 나라(2.0) |
| 문서 판정 | 줄 ≥ 8 · 글자 면적 ≥ 20% · 낱말표(합계·부가세·승인 / 원·메뉴 / 주차 / 운송장) | 종류(4.0) |

도구: PaddleOCR PP-OCRv5 ONNX(글자 찾기 2.3MB(v3 mobile)~84MB(v5), 한국어 읽기 13MB, Apache 2.0) — Node·브라우저 모두 `onnxruntime`로. Tesseract(kor)는 한·영 섞인 간판에서 약해 보조. 간판은 기울어짐·네온이 많아 **글자 찾기 모델은 v5**, 읽기는 한국어 전용 사전으로. 정답 세트의 영수증·간판 50장으로 먼저 잰다(10절).

### 7-2. 그림(임베딩) — 쌍둥이·장면·'우리가 간 곳'

- 사진마다 512차원 벡터 하나를 저장. 세 가지에 쓴다: ① 자른·보정한 사본 찾기(코사인 ≥ 0.95) ② 제로샷 라벨(음식·풍경·사람·셀카·반려동물·문서·바다·산·절·시장·눈·벚꽃·단풍·낮·밤 — 라벨마다 한국어·영어 문장 두세 개의 평균) ③ **우리가 간 곳**: 자리가 확실한 사진들을 지점별 프로토타입으로 두고, 모르는 사진을 kNN(코사인 ≥ 0.90, 3표 중 2표)으로 지점 후보.
- 모델: 폰·브라우저는 MobileCLIP2-S0 ONNX(43MB, 512차원, 256px; Apple 샘플 코드 라이선스), PC는 SigLIP 2(다국어, Apache 2.0)로 한국어 문장 검색까지. 둘 다 `transformers.js`(WebGPU 또는 WASM)·`onnxruntime-node`. 시각 닮음만 필요하면 MediaPipe ImageEmbedder(MobileNetV3, 수 MB, Apache 2.0)가 가장 가볍다.
- 라벨 문턱은 정답 세트로 정한다. 제로샷은 **후보를 줄이는 데만**(점수 ≤ 2.5) 쓰고 혼자 '확실'이 되지 않는다.

### 7-3. 사람 — 기본 꺼짐

- 켜면 얼굴 벡터를 기기 안에만 저장, "우리 둘"을 사용자가 한 번 이름 붙임. 쓰임: '우리 사진'(책·올리기 우선), 받은 사진이 우리 여행 사진인지(우리 얼굴이 있으면 +1.5).
- 모델: InsightFace 계열은 코드 MIT·**모델은 비상업 연구용** — 우리 둘이 쓰는 동안은 되고, 팔 때는 face-api 계열(MIT) 같은 다른 모델로 바꾼다. 라이선스 표를 코드 옆에 둔다.

### 7-5. 카드·결제·교통 기록 — 시각이 정확한 '자리 기둥'

카드 이용내역은 **분 단위 시각 + 가맹점 이름(+업종, 때로 주소·전화)**이 한 줄에 있어, GPS 없는 날의 가장 센 기둥이 된다. 사진이 한 장도 없는 끼니·숙소도 알려 주므로 여행 발견과 가계부까지 이어진다. 전부 **기기 안**에서만 읽고, 금액은 가계부 말고는 쓰지 않는다.

| 자료 | 어떻게 들어오나 | 주는 것 |
|---|---|---|
| 카드사 이용내역(엑셀·CSV) | 카드사 홈페이지·앱 '이용내역 내려받기'(월·연 단위). 카드사마다 열 이름이 달라 '이용일시·가맹점명·금액·업종' 열을 이름으로 찾는 **범용 읽기** + 카드사별 예외 표 | 시각(분)·가맹점·업종·(가맹점 전화·주소) |
| 승인 문자·앱 알림 | `[KB국민] 11/03 12:15 23,000원 주문진○○횟집 승인` 꼴. 네이티브 앱이면 문자 읽기 권한(개인용 APK만), 아니면 문자 내보내기 파일 | 시각·가맹점·금액 |
| 카카오페이·네이버페이·토스 거래내역 | 앱 내보내기 | 시각·가맹점(온라인은 자리 없음) |
| 교통카드(티머니·후불교통) 이용내역 | 카드사·티머니 사이트 내려받기 | **승·하차 역/정류장 + 시각** → 이동 경로 기둥 |
| 하이패스 통행내역 | 하이패스 사이트 내려받기 | 영업소(IC)·시각 → '이동 중' 구간과 방향 |
| 숙박·항공·기차 예약 메일(선택) | 메일 내보내기 또는 붙여 넣기 | 숙소 자리·투숙 밤, 비행·열차 시각 |

가맹점 → 자리: ① 보라핀 가게·관광지 기록과 이름 맞춤(편집 거리 ≤ 1) ② 가맹점명 속 지점 이름(`스타벅스 강릉안목점` → 강릉) ③ 카드사가 주는 가맹점 전화(지역번호)·주소 ④ 그래도 모르면 Kakao Local 키워드 검색(무료 한도, **가맹점 이름마다 한 번만, 결과는 목록에 저장**, 설정에서 끌 수 있음). 법인명(`(주)○○푸드`)은 ①~③이 안 되면 ④로.

점수(3-2 표에 보탬): 가맹점 자리를 아는 결제가 **사진 앞 2시간 ~ 뒤 15분** 안(밥은 찍고 나서 낸다) → 지점 4.0, 같은 날 같은 가맹점 반경 2km 안 → 3.0 / 지점 이름으로 지역만 알면 3.5 / 숙박 업종은 그날 밤~다음 아침 사진의 지역 3.5 / 교통카드·하이패스 사이는 '이동 중' 3.0(두 지점을 잇는 길).

쓰임 넷: 자리 기둥(위) · **여행 발견**(집 밖 숙박 결제 = 하룻밤 증거, 사진이 없어도) · 맛집 '다녀왔어요' 후보(결제 + 사진 묶음 → 가게 이름과 시각이 다 있음) · 여행 가계부(금액, 기기 안에서만).

걸러야 할 것: 온라인·배달·정기결제(업종·`쿠팡`·`배민`·`네이버페이 온라인` 낱말, 자리 없음으로) · 취소와 재승인(같은 금액·가맹점 10분 안 두 줄은 하나로) · 해외 결제(승인 시각은 한국 시각으로 오므로 여행 도시 시차로 바꾼 뒤 비교, 가맹점은 영문·현지 통화) · 동행이 낸 결제(보라 카드 내역도 같은 목록에 넣으면 메운다) · 가맹점명 ≠ 간판 이름(①~④ 순서).

### 7-4. 품질 — 컬링

라플라시안 분산(흔들림) · 밝기 히스토그램(노출) · 얼굴 랜드마크(눈 감음) · 연사 묶음(지각 해시 ≤ 10비트, 시각 ≤ 3초) 안에서 최고 한 장. 분류에는 안 쓰고 책·올리기 추천에 쓴다.

## 9. 정확도 재기

### 9-1. 가리고 맞히기 (자동, CI)

1. EXIF 시각·GPS가 다 있는 우리 사진 N장(처음 2,000장)을 고른다.
2. 무작위로 10% · 30% · 60%를 골라 **시각만 / 자리만 / 둘 다 / 전부(파일명·폴더까지)** 가린다. 받은 사진 흉내: 긴 변 1280으로 줄이고 메타를 벗긴 사본을 만들어 섞는다.
3. 알고리즘을 돌리고 가린 값과 견준다.
4. 지표: 날 맞음(±0일) · 시각 ±1시간 · 지역(시·군) 맞음 · 동네 맞음 · 여행 맞음 · 종류 정밀도/재현율 · 확신별 실제 정확도(6절 보정표) · 모르는 사진 비율 · 질문 하나당 풀린 장 수.
5. 결과는 `desk/bin/eval.ts`가 표로 내고 CI 보고서(`ci-report`)에 붙는다. 가중치를 바꾸면 이 표가 바뀌는 게 보인다.

### 9-2. 정답 세트 (사람, 한 번)

기획안 10절의 `정답세트/` 폴더(여행 폴더 10개 × 50장 안팎 + `여행아님/`). 가리고 맞히기가 못 다루는 얼굴 — 디카·스캔·받은 사진·영수증·간판 — 을 여기서 잰다. 폴더 이름이 정답이라 표가 필요 없다.

### 9-3. 목표 (1단계 끝 기준)

| 지표 | 목표 | 메모 |
|---|---|---|
| 날(시각 근거가 하나라도 있는 사진) | ≥ 98% | 기획안 10절 그대로 |
| 지역(시·군) | ≥ 90% | GPS 없는 사진 기준 |
| 동네 | ≥ 70% | 기둥이 가까울 때만 가능 |
| 여행(기록된 여행 날짜 안 사진) | ≥ 95% | |
| 자료 가르기 | 정밀도 ≥ 95%(여행 사진을 자료로 잘못 숨기지 않기), 재현율 ≥ 85% | 숨김이라 재현율보다 정밀도 |
| 확신 보정 | 확실 ≥ 97% · 추정 ≥ 80% | 어긋나면 문턱 조정 |
| 모르는 사진 | 메타만 → 이음 → 글자 → 그림 → 질문 5개, 층마다 줄어드는 것이 보여야 | 예상: 40% → 20% → 15% → 10% → 3%(우리 사진으로 확인) |

| 서비스 | 무료 한도 | 쓸 수 있는 것 | 왜 기본 끔 |

| Cloudflare Workers AI(이미 물어보기에 씀) | 하루 10,000뉴런, 00:00 UTC 초기화 | `@cf/microsoft/resnet-50` 분류, 이미지→글 모델로 '설명 한 줄' | 사진이 밖으로 나감. 켜면 "모르는 사진 상위 50장만" 같은 한도 |
| Google Vision · Azure Vision | 월 1,000 / 5,000장 안팎 | 랜드마크·OCR | 같은 이유 + 키 관리 |
| Open-Meteo 과거 날씨 | 무료·키 없음 | "그날 그 지역에 눈" 같은 계절 검산 | 재미 수준, 뒤로 |

결론: **1단계는 바깥 호출 없이** 메타·이음·글자·그림(기기 안)으로 간다. 바깥 AI는 설정에서 켜는 보너스.

## 11. 만드는 순서 (1단계 안의 순서)

모두 **순수 함수** `desk/src/infer/`에, 시험은 `tests/desk/`, 채점은 `desk/bin/eval.ts`. 층을 하나 올릴 때마다 9-1 표에서 '모르는 사진'이 줄어야 다음으로 간다.

| 차례 | 모듈 | 내용 | 끝나는 기준 |
|---|---|---|---|
| 1 | `evidence.ts` | 3절 증거 조각 꺼내기 + `WEIGHTS` 표 | 조각 단위 시험(이름·폴더·영수증 날짜 정규식) |
| 2 | `links.ts` | 순번·쌍둥이(해시·dHash)·다른 폰·폴더 이음 | 가리고 맞히기 '시각만 가림'에서 날 ≥ 95% |
| 3 | `when.ts` · `clocks.ts` | 구간 합치기·충돌·시계·시간대·낮밤 검산 | 디카 시계 오차 제안이 정답 세트에서 맞음 |
| 4 | `where.ts` | 기둥 보간·묵은 좌표·속도 검산·글자 기둥(글자는 입력으로 받음) | '자리만 가림'에서 지역 ≥ 90% |
| 5 | `events.ts` · `trips.ts` | 날·자리 묶음·나들이/여행 묶음·여행 맞추기·여행 발견 | 여행 ≥ 95%, 기록 없는 여행이 제안됨 |
| 6 | `kind.ts` | 자료·받은 사진·일상·나들이·여행 + 고친 규칙 번짐 | 자료 정밀도 ≥ 95% |
| 7 | `ask.ts` | 질문 고르기·답 번지기·세 바퀴 | 질문 5개로 모르는 사진 절반 이하 |
| 8 | `eval.ts` + `bin/eval.ts` | 가리고 맞히기·정답 세트 채점·보정표 | CI 보고서에 표가 붙음 |
| 9 | `ocr/`·`embed/`(PC 앱·브라우저 각각) | 7-1·7-2를 돌려 목록에 저장하는 어댑터 | 영수증·간판 50장 시험 통과 |

화면(폰 서랍·윈도우 앱)은 `Inferred`를 읽어 보여 주기만 한다: 사진을 열면 근거 한 줄, 묶음 머리에 "확실 31 · 추정 6 · 모름 2", 확인함 탭에 질문 다섯.

## 12. 위험과 한계

| 위험 | 대비 |
|---|---|
| 잘못 번짐(틀린 기둥 하나가 하루를 물들임) | 기둥은 4.0 이상만, 묵은 좌표·속도 검산, 번짐은 깎인 점수로(혼자 '확실'이 되지 않음), 근거가 보여 묶음째 고침 |
| 두 사람 사진이 한 목록 — 상대가 그날 다른 곳에 있었던 경우 | 다른 폰 이음은 거리 검산(둘 다 GPS면 ≤ 500m) + 보라핀 여행 '같이 간 사람' 기록이 있으면 그때만 |
| OCR 오독(지역번호 비슷한 숫자) | 고유 일치만 3.5, 숫자 규칙은 형식까지 맞을 때만, 영수증은 가게 이름과 지역번호가 같은 지역을 가리킬 때 점수 합 |
| 모델 크기·속도(폰) | 폰은 S0(43MB)·WASM, 후보 사진만 돌림. 전체는 PC |
| 라이선스(얼굴 모델 비상업) | 기본 꺼짐 + 팔 때 교체 표 |
| 확신이 실제와 어긋남 | 9절 보정표를 CI에서 매번, 어긋나면 배포 중단(물어보기 95% 규칙과 같은 식) |
| 사람의 답이 틀림 | 답도 되돌릴 수 있고(장부), 답과 충돌하는 강한 증거(EXIF)가 있으면 '충돌'로 다시 묻는다 |
